11 / TUTORIAL
HOW TO READ FINDINGS

1. IMPORT EVIDENCE

Select sysdiagnose extracts, readable logs, PLIST, MOBILECONFIG, IPA or TIPA files. The current browser tool rejects individual files over 50 MB. ZIP contents are scanned within safety limits.

2. READ DATES AND FILE DETAILS

TIME is shown only when a timestamp is present in the evidence. File modified time is device/browser metadata and is not necessarily the time an event occurred. Archive entries without an explicit timestamp are marked as unknown.

3. APP ICONS

The tool can attempt live App Store icon lookup for recognized public apps. Some apps are not listed publicly, are region-limited, or use identifiers that cannot be matched; those will keep a neutral fallback. Icon availability does not prove installation.

4. PROXY, DNS AND JAILBREAK INDICATORS

A proxy or DNS event alone does NOT prove jailbreak. Correlate several independent records, paths, timestamps, profile/certificate details, and known jailbreak artifacts. Results are indicators, not a definitive jailbreak verdict.

5. IPA, FILZA, TIPA, TROLLSTORE AND RELATED ARTIFACTS

A filename, bundle ID, or string match can mean a package was mentioned, cached, downloaded, or merely included in a log. Look for explicit installation/lifecycle records before concluding that an app was installed.

6. ACCESS LOGS AND OWNER DASHBOARD

This single HTML file cannot securely register visitors or send you real-time login records. Browser-only logs can be edited or cleared and are not shared with the owner. Real tracking of logins requires a hosted backend, server-side authentication, database, and an owner-only dashboard. Record only necessary security metadata, disclose logging in a privacy notice, and do not attempt to identify people from device fingerprints or approximate location alone.

7. HOW TO INTERPRET THE APPLICATIONS SECTION

Each card should show the app name, icon when it can be verified, the exact Bundle ID, TIME, status, reason, source file and nearby evidence. The Bundle ID identifies an app or component; it does not by itself prove that the app was installed. An extension can share the parent app's identity, so its icon may be the parent's icon only when that relationship is known.

8. HOW TIME IS CHOSEN

The analyzer must use a date/time found near the specific Bundle ID or lifecycle event in the source text. It must not borrow a date from another part of the file, use the file's modified date as an installation date, or interpret build numbers / version numbers as timestamps. Duplicate records with the same Bundle ID, action and timestamp should be collapsed. If a source only contains a date, the interface should not invent a time of 00:00. If no timestamp is linked, it must say so.

9. SUSPICIOUS FILES AND WHAT THEY ARE FOR

Filza: file manager commonly used to browse files and folders that the normal Files app may not expose. A Filza reference may come from an app identifier, a downloaded package, a log or an actual installation; inspect the source and event. IPA / TIPA: app package files. Their presence can indicate a download, transfer or archive; it does not prove successful installation. MobileInstallation / mobile_installed: installation-related system records or directories. These are more useful when a Bundle ID and an event timestamp appear together. TrollStore / Persistence Helper: references associated with a third-party app installation mechanism. A string match alone is not proof it was active. eSign / GBox / Scarlet / AltStore / SideStore: names associated with signing or alternative app distribution tools. Verify app identity, profile, certificate and installation evidence independently. TrollFools: app-modification related reference. Check the exact path, package and surrounding logs before drawing a conclusion. Dopamine / ElleKit / Substitute / MobileSubstrate / Sileo / Zebra / Cydia: names associated with jailbreak or package-management ecosystems. These indicators require corroboration and can appear in downloaded files or copied text. .mobileconfig / MDM / VPN / DNS / Proxy: configuration and network artifacts. They may be legitimate work, school, privacy or network settings and are not by themselves proof of compromise. .mobileprovision / certificates: signing and provisioning metadata. Presence does not prove that a certificate was trusted or that an app ran.

10. CHECKING A FINDING STEP BY STEP

1) Read SOURCE first and note the exact filename/path. 2) Read EVIDENCE and check whether the text explicitly says installed, removed, revoked, downloaded, synced, or not installed. 3) Search the same file for the Bundle ID and its nearest timestamp. 4) Compare with independent records such as MobileInstallation, app state, profile/certificate records, or a second log. 5) Treat contradictory messages such as “SYNC DISABLED (app not installed)” as a negative/non-installed indication, not as an installation confirmation. 6) Keep the original file unchanged and preserve its hash if the result matters.

11. LIMITS

No detector can guarantee every App Store app, every jailbreak artifact, or an exact factory-reset date from arbitrary logs. Missing timestamps are shown as unavailable instead of being invented.
